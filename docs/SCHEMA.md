# Dataset contract

`data/labs.json`. Modelled on [FHIR R4 Observation](https://hl7.org/fhir/R4/observation.html),
extended with a `provenance` block that FHIR has no concept of: which pixels this number
came from.

**Every module in `src/` reads and writes this shape. Change it here first.**

> Every value below is from the synthetic case (`docs/SYNTHETIC-DATA.md`) — invented data,
> generated by `tools/make_synthetic.py`, which is also what a fresh clone of this
> repository produces. Identifiers are `SYN…` by construction. Real patient values never
> appear in a committed file: the pre-commit guard blocks it, and it did block an earlier
> draft of this very document.

## Rules that the shape enforces

| Rule | Why |
|---|---|
| `analyte` is always a key in `config.ANALYTES` — never free text | one vocabulary, so trends join across days |
| ABG analytes carry the `abg_` prefix and never merge with serum equivalents | different specimen, method and reference range; MELD needs the **serum** sodium (`docs/DECISIONS.md` D13) |
| `value` is `null` for qualitative results; `text` is `null` for quantities | a culture result must not be coerced into a number |
| `collected` comes from the grey band, carried forward on continuation pages | half the pages have no band of their own (`docs/DECISIONS.md` D4) |
| `reference_text` keeps the page's own wording; `reference` keeps the parsed bounds | the parse can be wrong, and the evidence for that is the original string |
| `provenance.human_verified` must be `true` for any observation that reaches a chart | `build.py` fails the build otherwise (`docs/VALIDATION.md`) |
| `complete: false` scores render as incomplete, listing `missing` | never substitute a default for an unrecorded clinical finding |
| every score carries `band` — the class or bin (`"A"`, `"II"`, `"30-39"`, `"severe"`), `""` when incomplete | the number and the label are computed together in `src/scores.py`, so the UI cannot invent a different set of boundaries |
| every score carries `notes` — caveats about the inputs, usually `[]`, and kept even when `complete: false` | AARC's lactate is the blood-gas one, not the serum assay it was derived on; a substituted specimen is stated, never dropped |

## `unit` is the canonical unit, and that is a trap

`build.py` deliberately replaces the OCR'd unit with the one `config.ANALYTES` declares —
otherwise every wrapped or corrupted unit string (`10^3/mm^` + `3`) reaches the screen. The
substitution is right for most analytes and was **wrong, by a factor of 1000, for one**:

| Analyte | Page prints | Values | Unit once declared | Rendered as |
|---|---|---|---|---|
| `platelets` | `10^3/mm^3` | 131 – 148 | `10^3/mm^3` | correct |
| `rbc` | `cells/cumm` | 3.21 – 3.42 | `10^6/uL` | correct |
| `wbc` | `cells/cumm` | 9 900 – 19 100 | ~~`10^3/mm^3`~~ | **`19100 10^3/mm^3`** — 1.9 × 10⁷ white cells/µL |

The rule could not simply be reverted: the same substitution is what makes `rbc` and
`platelets` readable. The fault was declaring a thousands unit for an analyte this report
prints as an absolute count.

**The detectable signature, and the fix:** `config.ANALYTES["wbc"]` declared the envelope
`lo=0.05, hi=200` (thousands) while the stored values were five-digit absolute counts. A
display unit and a physiological envelope that disagree about scale cannot both be right,
and neither the envelope gate nor the unit substitution noticed the other. `wbc` now
declares `unit="cells/cumm", lo=50, hi=200000`, and unit and envelope are edited together
because they are one statement about scale in two fields.

## Day indexing

`day` is a 1-based index over calendar days from the first collection, not a count of
samples. Several samples share a day; the dashboard groups by it. Days with no sample are
still days: the axis is time, not measurement order.
